# 第 4 步构建记录

状态：v1 非金额履约子集已实现；Muse 于 2026-10-24 给出有条件通过。Codex 已修正空单清单状态、补反向权限断言并重拍 iOS 模拟器截图，现作为 v2 任务书 §7 的关闭证据。v2 已开始实施：数据库会在首单创建后冻结票价、尾角加价、整航次门槛与包船价；下单事务锁定班次行，避免价格更新与首单并发绕过冻结。其余 A–E 尚未完成；本文不表示第 4 步全量验收或真实交易获准。

## 范围

已实现：

- 船长只查看已确认、出海中和已返航的班次。
- 服务端为已确认班次生成行前清单，并在沙盒通知发件箱留记录。
- 船长出航、返航打卡推动班次状态，重复打卡会被拒绝。
- 船长可导出掩码或完整实名名单；两种导出均写入审计记录，完整名单仅船长本人可取。
- 钓友可查看订单对应的出航时间、集合码头和已生成的行前清单。
- 清单与通知不调用真实天气、短信、支付或保险服务。

暂缓：

- 成团金额、违约金池与最低成行总价核算。
- 少人成行、补差报价/扣款与失败回滚。
- 包船结算与候补递补。
- 乘客取消、爽约、退款及退改阶梯执行。

以上涉及 D02 或被 Muse 当前状态注记列入暂缓边界。不能把代码或界面推演当作已获批准的资金规则。
