# 创始人决定：第 6 步切片 1 退款重订选 B（2026-10-27）

## 决定

创始人于 2026-10-27 07:07 CST 在海钓专属侧聊点选定版（选项原文：「选 B：未取消且净额>0才算首单」）：

> **B：仅首笔未取消且净票款大于零的订单消耗首单计佣资格。**

A（首笔付款即消耗资格）不采用。本决定自入仓起生效，Luna 按本单改实现；Dot 此前明示不代选 A/B，本单即其所待的创始人决定，改后仍须 Dot 定点复核。

## B 口径（定版）

1. **首单的选取**：在被推广人的已付款订单中按付款时间升序，取第一笔**未取消且净票款 > 0** 的订单为计佣首单。净票款口径不变：`seat_fee − discount − ticket_refunded`。
2. **全退/取消不消耗资格**：首笔订单若全额退款或取消（净票款 = 0），不消耗该被推广人的首单资格；其佣金保持归零/回滚。之后同一被推广人重新下单并支付成功、且该单未取消、净票款 > 0 的，该重订单成为计佣首单，按其净票款 × 5%（向下取整）计佣，状态机照常（冻结→返航完成→完成 +7 天解冻→提现）。
3. **部分退款不顺延**：订单部分退款但净票款仍 > 0 的，仍是首单，按净额重算佣金，不把资格顺延到后面的订单。
4. **只计一次不变**：同一被推广人、同一实名身份最终只消耗一次首单资格、只产生一份有效计佣；重订是资格顺延，不是多给一次。自推无效、无成交不产佣、一级 5% 等既有规则全部不变。

## 现行实现与定版的差异（待 Luna 改）

现行 `syncPromotionForUser` 取首笔已付订单（按 `paid_at` 排序，不论其后是否取消），且 `order_id` 以 `COALESCE` 锁定——首单全额取消后，重订不再计佣。此实现对应未被采用的 A。Luna 须把首单选取改为上述 B 口径，并处理资格/账本从已归零首单顺延到重订单的迁移：原归零账本留作历史事实，不删改历史；顺延后总计佣仍只有一份有效账本。

## 与 R1 已关闭结论的边界（不得借 B 重开）

- R1 的跨账号防线不变：某实名身份曾被账号 A 消费资格的事实记录（迁移 021–023 与身份 HMAC 事实）继续有效；账号 B 复用同一身份仍返回 `identity_already_qualified`，B 口径不解除该拦截。
- B 的顺延只适用于**同一被推广人本人**的订单之间（首单全退→本人重订）。实现时须区分「本人顺延」与「他人复用身份」，并用例覆盖（见验收第 5 条）。
- 已解冻后退款的处理不变（R3/Q2 已裁定）：不追缴、不扣款，只标注异常落事实。「首单已完成并解冻、其后全退、又重订」的组合情形如有歧义，按 R3 既有口径处理并在回执中单独说明，不得自行扩义；有争议交 Dot 裁定。

## 验收用例（Luna 必须补齐并在回执逐项映射）

1. 首单支付成功→全额退款/取消→同一被推广人重订支付成功：重订单成为计佣首单，佣金 = 重订单净票款 × 5%，状态机从冻结正常起步；原单佣金为 0 且历史留痕。
2. 首单全退后**没有**重订：无计佣、无有效首单，会员有效资格不被该笔全退订单消耗（后续若再下单，按第 1 条处理）。
3. 首单部分退款、净票款 > 0：仍为首单、按净额重算；其后新订单不计佣。
4. 首单正常成交后又下一单：第二单不计佣（只计一次）。
5. 跨账号边界（R1 回归）：A 曾以身份 X 消费资格（含 A 首单全退归零的历史路径）→ A 更正为 Y → B 以 X 付首单，仍被 `identity_already_qualified` 拒绝、无第二份账本；同时 A 本人以更正后身份/本人后续合格重订单的计佣不受此拦截误伤。
6. 顺延的幂等与并发：同一重订单重复同步/并发同步只产生一份有效账本、只消费一次资格。
