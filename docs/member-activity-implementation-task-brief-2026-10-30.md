# 任务书｜会员发起活动（需求单与双向撮合）实现（沙盒）

- 下单：Muse；执行：Luna 开发会话。先回执后动手。
- 排期依据：创始人 2026-10-30 点选「先排会员发起活动」，定为下一批开发首项（证书分页多图排其后）。
- 规格依据：提案 `docs/proposal-member-initiated-activity-2026-10-28.md`（入仓 `11923af2`）与 `docs/current-rules-index.md` 现行口径。本任务书与提案冲突时以本任务书为准；与创始人决定冲突时以创始人决定为准。
- 范围总界：**仅沙盒/接口层**。不授权真实资金、真实保险出单、真实推送通道、生产部署。

## 一、要做的

1. **需求单**：实名会员可创建/编辑/关闭需求单。字段：日期与时段、出发码头、海域/目的地、人数、包船或拼船、目标鱼/钓法、预算区间、装备与同行要求（新手/儿童等）、备注。状态机：已发布 → 已转化 / 已关闭（会员手动）/ 已下架（到期自动）。护栏（沙盒初始值，做成可调参数）：发布须实名校验通过；同一会员同时有效需求单 ≤3、自然日新发 ≤3；有效期到出航日期或发布后 7 天先到者，到期自动下架。
2. **需求广场（船长端）**：浏览已发布未到期需求单，可按码头、日期、人数、目标鱼、包船/拼船筛选。
3. **双向匹配（站内记录，不接真实推送）**：需求发布后，按维度匹配船长并生成站内通知记录——档期空闲（该船该时段无已确认班次冲突）、容量满足（包船：整船容量 ≥ 需求人数；拼船：对应班次余位 ≥ 需求人数）、码头一致或在船长服务码头内、目标鱼命中船长标签/历史。反向：把符合该需求的既有公开班次以站内消息推回会员。匹配只产通知记录，不自动建班次、不自动下单。
4. **船长邀约**：船长以自有价对需求单发邀约——包船给整船价，拼船给人均价与成团门槛（B1 口径）；邀约含船、码头、时段、集合点。同一船长对同一需求单至多一份有效邀约，可撤回；船长之间互不可见对方价格，平台不做竞价、比价排序或拍卖（首期不做多船竞价）。
5. **确认转化**：会员择一确认邀约后，系统经既有班次/订单创建路径生成正式班次（船长、价格、门槛按邀约冻结，适用价格冻结规则）与订单入口，后续全走既有规则：全款预付托管、保险必买、退改阶梯、B1 成团核算、选位、F01 候补。需求单转「已转化」并关联班次 ID；其余未确认邀约自动失效。包船需求生成的必须是零预订新班次，不得触碰任何已有预订班次（禁挤人决定衔接）。
6. **防跳单**：需求单、邀约与站内沟通一律不展示、不传递联系方式；备注与消息内容对手机号/微信号类模式做过滤拦截。沟通只走站内消息（沙盒实现消息记录与已读状态即可）。
7. **事实记录**：船长响应、邀约撤回、确认后爽约/取消只记事实（沿用事实层只追加原则），不生成评分、不排名、不卖排名。

## 二、明确不做

多船竞价/拍卖；拼船需求凑人成团的强化形态与定价建议（二期候选）；免费约钓帖（计划 §十九，非商业组局，不在本单）；真实推送通道（短信/微信/系统推送）；新交易逻辑或第二套订单/支付代码（转化必须复用既有路径）；改动任何已有班次、订单状态的入口。

## 三、实现与验收口径

- 数据层沿用既有迁移编号续编与命名风格；需求、邀约、匹配、消息各表职责单一，状态流转留痕。
- 沙盒断言至少覆盖：未实名发布被拒、超限频被拒、到期自动下架；广场筛选正确；匹配命中与四类不命中（档期冲突、容量不足、码头不符、目标鱼不符）；邀约唯一性与撤回；确认转化生成班次且价格/门槛冻结、需求单关联班次、其余邀约失效；转化班次可走既有下单链路（沙盒支付）；联系方式过滤生效；需求单全流程不改变任何既有班次状态。
- 回执要求（先回执后动手）：确认本任务书口径、拟用迁移号、匹配规则实现方式、转化复用既有路径的具体落点；口径疑问先在回执中提出问 Muse，不自行发明规则。
- 交付后走既有评审链：Muse 评审 → Dot 复核 → 创始人产品验收；关单仅限沙盒范围，不构成生产放行。

## 四、备查

- 限频数值与 7 天默认有效期为沙盒初始值，上线前由创始人复核可调，不阻塞本单。
- 竞品参照（背景，非规格）：一起海钓现行同类需求报价模式；本单按约钓者既定规则实现，不照搬其会员收费与竞价形态。
