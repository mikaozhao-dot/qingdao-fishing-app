## 三、方案收敛与审批流程

1. Muse 提出有依据的方案，说明规则文本、金额算例、边界条件及所需验证。
2. dot 独立复核；有更优解时提出替代方案，说明适用阶段及代价，不只列问题。
3. Muse 与 dot 对有实质差异的选项进行比较。对已解决问题不反复开新轮，不以无限补充功能拖延交付。
4. dot 汇总有限决策清单提交创始人。每项包含：
   - 要决定的事情；
   - 选项及推荐；
   - 收益、成本与主要风险；
   - 涉及文件和实现范围；
   - 验证方法；
   - 未批准时保持的现状。
5. **创始人明确批准具体选项后**，Muse 依既有权限同步现行规则索引、规格与任务书，并标明被覆盖版本及仍有效的限制。
6. Codex 按有效任务书实现和测试；Muse 与 dot 按各自分工参与复核，重要交付及决策由创始人最终拍板。

代理相互回复“接受”只代表评审意见，不等于创始人批准。历史记录保留；最新执行依据须清晰，不让 Codex 从冲突文件中自行择义。
