# 数据模型增补 · 第 4 步（非金额履约部分）

本增补只覆盖已经放行的出航与返航履约能力。成团金额核算、违约金补偿池、补差、包船、退款与退改执行继续等待创始人完成 D02 裁定；本增补不定义或实现这些规则。

## 本次新增

### departures

- 新增 weather_note，用于清单中的出航前海况提示占位。
- 状态约束增加 in_progress，用于 confirmed → in_progress → completed 的出返航打卡流转。
- 保留原有状态及字段；不在本增补中增加或变更金额计算字段。

### departure_pretrip_checklists

- 每个班次最多一条当前清单，按 departure_id 唯一。
- checklist 保存集合时间、码头、海况提示、保险状态、乘船人和已订座位核对结果，以及逐项清单。
- 只对服务端已经处于 confirmed、in_progress 或 completed 的班次生成，不参与成团判定。
- 生成清单时在 notification_outbox 记录沙盒站内通知，不发送短信或外部消息。

### departure_checkins

- 记录 captain_user_id、班次、departed / returned 事件和时间。
- 同一班次每种打卡事件唯一，防止重复推进状态。
- 出航打卡只允许 confirmed 班次；返航打卡只允许 in_progress 班次。

### departure_passenger_gate_decisions（迁移 018）

- 每个班次和已支付乘客保留当前一次服务端准入决定：`allowed` 或 `blocked`，同时记录保障状态、适用保障记录、船长与决定时间。
- `allowed` 必须对应当前出航时段内 `effective` 的乘客保障；非生效状态记录为 `blocked`，并带明确阻断原因。拒绝全船出航时可保留这些乘客级阻断结果，但不写 `departed` 打卡，也不改变班次状态。
- 出航后的名单只包含 `allowed` 乘客；未获准者不会进入实际乘船名单。再次检查会更新该乘客的当前决定行，不是不可变的逐次尝试日志。
- 该表用于沙盒准入与可追溯结果，不记录真实保单、不改变订单/账目，也不替代保险服务端的承保核验。

### manifest_export_audit

- 记录班次、船长、导出格式、行数和导出时间。
- 不保存姓名或证件号。完整名单只在通过权限校验后临时生成，并由船长本人导出。

### notification_outbox

- 仅记录 channel=sandbox 的通知内容和接收人。
- 班次、用户和通知类型组合唯一，避免重复生成清单通知。
- 不接短信服务商、推送服务或生产消息队列。

## 暂缓建模

以下实体与交易状态暂不进入本次迁移：成团决策、补差报价/收款、退款流水、船长应收、补偿券、候补队列和退改阶梯。待创始人裁定 D02 并收到修订版任务书后另行建模。
