# Codex 开发任务书 · 第 1 步：账号与船档案

依据《开发路线图 v1》第 1 步、《产品计划》§十三（产品结构定版）与第 0 步评审（docs/step0-review-2026-10-24.md）。本步只做账号、实名、船长入驻与船档案审核，不做班次与交易。

## 交付物

### 1. 后端（server/ 扩展，新增迁移自 002 起，不改 001）
- **账号**：手机号+验证码注册/登录。短信走适配层接口+沙盒实现（测试码仅限非生产环境，须在 build-notes 注明规则）；登录态用 token；手机号唯一性以已预留的 HMAC 摘要查重。
- **实名**：提交姓名+身份证号，状态机 未提交→审核中→已验证/驳回；核验走适配层沙盒（格式与校验位规则+测试号段）。PII 只存密文（模型已预留字段），接口响应与日志不得回明文。
- **船长入驻**：资质提交（与实名关联、证件照片）+船档案全字段：船名、长度、登记信息、照片四类（外观/甲板/船舱/厕所）、设施勾选（用产品计划固定清单：厕所、船舱、活鱼舱、鱼探、空调、夜钓灯）、默认集合码头（小港/积米崖/沙子口/田横/红岛/中港）。照片经对象存储接口落 URI，本地可用桩存储实现，接口形态按可替换设计。
- **最小管理后台**：与 API 同仓同部署的最简 Web 页；待审队列（资质+船档案同一流），通过/驳回（驳回必填理由、回显给船长），审核动作留痕；管理员口令走环境变量，不入仓。
- **自动生成（本步核心）**：船档案提交后按船长生成——①钓位模板：12–14m 套定版 12 位模板（二维、编号从船头左侧顺时针、6/7 为尾角加价位），模板 code 落库；②舒适度标签：平台计算，间距估算=(船长−2m)÷6（每侧，v1 估算口径待实船校准），≥1.95m 宽松、1.75–1.95m 舒适、<1.75m 紧凑；标签只读，船长端无修改入口。12–14m 之外的船照常登记，模板置「待人工」并在后台标注，不自动套图。

### 2. App（按冻结设计系统 tokens 排版，十屏未覆盖页保持同风格）
- 登录/注册页、实名提交与状态页；
- 船长入驻流：资质提交→船档案表单（能勾选的不打字）→状态页（审核中/已通过/驳回含理由）；
- 船长端「我的船档案」页：展示自动生成的二维钓位模板图与舒适度标签（只读）。

### 3. 文档
- `docs/step1-build-notes.md`：逐项对应下方验收的自检证据（含版本号、已知问题）。
- 数据模型增补只写增补说明，不改已发布口径；字段变更逐项列明。

## 约束
- 不接真实短信/实名/支付/保险供应商（适配层+沙盒）；任何密钥、凭证、真实口令不入仓。
- 不生成 seat_inventory 实例（第 2 步发班时才生成），本步只落模板与标签。
- 不得修改规格正本；一类交付物一提交；提交说明说清内容。

## 验收（Muse 实跑，对应路线图验收句）
1. 用构造样例船（13m、设施齐全、四类照片，字段口径与真船一致；不等待 BD 真船）走完：注册→实名→入驻提交→后台驳回一次（理由在船长端回显）→修改重提→审核通过，状态全程正确。
2. 通过后核：钓位模板已生成，编号顺序与尾角位与定版一致；舒适度标签按公式自动得出。
3. 查库核 PII：users/船长相关表无明文手机号与身份证号。
4. **关闭第 0 步遗留两条件**：附 `flutter analyze` 全量通过输出；附模拟器或真机冒烟记录（本步主要页面截图 ≥3 张，每张 <1MB 入仓）。
5. Muse 侧独立实跑主链路接口（注册/登录/实名/入驻/审核）复核后出评审文件。
