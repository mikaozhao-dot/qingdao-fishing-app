## 必修四项（Dot 原编号与口径，不得改写）

### F1 ＝ S6-S1-R1：实名唯一 ≠ 历史资格只用一次

现状：迁移 `021` 只对用户**当前**已核验身份摘要建唯一索引；实名接口允许已实名账号改成另一摘要、失败时清空摘要；计佣侧没有历史身份资格消耗检查。确定反例：A 用身份 X 完成首单计佣 → A 更正为身份 Y（或实名失败使 hash 清空）→ B 使用 X 再次实名并首单计佣——X 可产生第二次资格，违背「同实名身份只计一次」。

最小修复：持久保存发生资格消费时的身份 HMAC 事实，以数据库约束/事务防止跨账号及并发重复消费；补上述真实 API 顺序用例及资格竞争用例。**不得**以未经批准的「禁止实名更正」替代修复。本项不代选退款重订 A/B（见业务边界）。

### F2 ＝ S6-S1-R2：无效自推被客户端当成归因成功终态

现状：`app/lib/main.dart:169–188` 不读 claim 响应体，任意 HTTP 200 都置 claimed 并清空 pending；服务端对 `claimed:false/self_referral`、`no_active_referral` 也返回 200。确定反例：先扫自己的码被正确排除后，同访客 token 再扫他人有效码，客户端因 token 已缓存为 claimed 直接跳过，首次有效归因无法建立；旧请求进行中到达的新 token 还会被旧请求完成时无条件清掉。

最小修复：按 `claimed/reason` 识别真正终态；无效触点不阻止后续有效触点；仅清理本次已处理项，并继续处理期间到达的新项。补 AppShell 实际接线测试：「自推 → 同 token 他人有效码」「无效领取处理中收到新有效 token」。现有推广 widget 测试（只测 token 格式与看板渲染）不能代替领取链路证据。

### F3 ＝ S6-S1-R3：历史退款被误记为解冻后异常

现状：`server/src/promotion-service.js:130–151` 后半分支只看累计 `ticket_refunded_fen > 0`，未限定真正已解冻状态、未识别解冻后是否发生新增退款。两条确定路径：①冻结期全额退款已 `reversed`，买家再次同步即误标「解冻后退款」；②冻结期部分退款已减佣、之后解冻且无新增退款，再同步仍误标异常。

最小修复：限制适用状态，并对比解冻基线后的新增退款；上述两例应无异常，真正解冻后新增退款才记录事实，重复同步不得重复追加。保留已批准的「不追缴、不扣款」范围，不因修复发明资金回收规则。

### F4 ＝ S6-S1-R4：深链插件与 Flutter 默认处理器未隔离（配置必修＋补证）

现状：使用 `app_links`，但 AndroidManifest 与 iOS Info.plist 只加了 scheme，未关闭 Flutter 默认 deep linking。实际 CI 使用 Flutter 3.47.8；官方迁移说明明确自 3.27 起第三方插件（含 `app_links`）需将默认处理器设为 false。

最小处理：补 Android `flutter_deeplinking_enabled=false` 与 iOS `FlutterDeepLinkingEnabled=false`，或提供当前版本等效处理的可核验证据；补相应构建的 H5 点击 → 冷/热启动 → token 保留 → 登录后实际 claim 的证据。注：Dot 未在真机复现冲突，此项不冒称已有设备故障；URI 字符串解析测试不能证明原生跳转成功。
