## 已核对的当前代码事实

1. 普通锁位、建单都要求班次 `status='open'`，并受 `booking_deadline` 与 `confirmation_at` 限制。成团检查把未达标班次置为 `handling_shortfall` 后，当前普通购票入口已关闭。
2. B1 `POST /captain/departures/:id/supplement-rounds` 只允许对 `handling_shortfall` 发起一轮；参与者由该时点已有付费订单冻结，核算快照与来源订单集合也会复验。失败或超时后拒绝第二轮。
3. `processSupplementDeadlines` 只使 B1 轮次失效并处理退出者的退款义务；当前实现搜索未发现对 `handling_shortfall` 班次执行第 4 级自动取消、全额退款和候选活动推荐的收尾作业。
4. 当前 server/app 中没有已实现的整船包船转换 API 或购买入口。因此本项没有现成的转换路由可加拦截；不能仅凭数据库中的 `whole_boat_price_fen` 字段假定已有行为。

## 需要定下的最小实施口径

请 Muse 对以下建议确认或修订后，作为本项实施任务书：

1. **第三级购买方式**：建议只开放对未售座位的标准票价购票，使用现有订单、乘客实名、保险名单和沙盒支付流程；达到 B1 门槛后服务端确认成行。不得在 B1 轮次已结束后再给原订单乘客加开补差，也不另造一个面向新买家的现金补差轮次。若产品必须支持“无对应座位的直接补足差额”，请指定其如何归入现有的一轮 B1 及其参与者/金额快照。
2. **第三级截止时间**：现行 `booking_deadline` 已在未达标处置前经过，不能直接复用。建议由 Muse 指定一个单一救援窗口终点；不得由实现者自行设定窗口时长。B1 轮未用或提前失败时该终点也必须确定。
3. **第 4 级收尾**：由于当前代码未找到所述自动取消链，建议本项补齐必要的沙盒收尾：窗口结束仍不达门槛则锁定班次、全额退款原有效订单、结清在途沙盒款/退款义务、释放未完成锁位，并返回/提供同码头同期替代活动。若该收尾应单独成项，请明确拆分及依赖；第三级不能在没有有界失败终态时上线。
4. **整船包船禁挤人**：当前无可执行入口。建议本项不创造整船转换功能；若评审发现另有实际入口，请给出路由/调用证据并纳入同一服务端有效乘客门禁。零有效预订班次的整船包船仍不在本项实现范围内。

## 实施验收建议

- 已有有效乘客时，任何整船转换请求均拒绝，且订单、乘客、座位、退款记录不变（仅在确认存在转换入口后适用）。
- 第三级只能售出当前未售座位；并发锁位不得超卖；新购买者与既有乘客同船，既有订单和座位不变。
- 新付费后按现行 B1 可核验口径重新计算；达门槛才由服务端确认成行，未达门槛不得前端自报成行。
- 截止仍未达门槛时执行已批准的第 4 级全额退款；幂等重跑不重复退款、不改变既有乘客退款权利。
- 测试仅限接口/数据库沙盒，不接真实支付、保险、生产或上架；不改规格正本。
