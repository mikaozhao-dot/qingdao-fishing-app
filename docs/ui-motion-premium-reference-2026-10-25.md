# 设计参考（非规格变更）：六种高级感微交互，产品可借鉴清单

日期：2026-10-25 20:29 CST。来源：创始人问「Codex 制作产品是否可以借鉴这些高级感」，Muse 答可以并落地本清单。性质：**设计参考与动效语言借鉴**，不改任何已定规格与排期；实现排在交易链路之后（随 UI 打磨批次），不插队当前第 4 步收尾与今晚宣传片。

## 借鉴映射（效果 → 约钓者落点）
1. **完成反馈按钮**（点按后变形确认）→ 预订提交、选位确认、支付成功态：动作有回音，不用额外弹窗。
2. **勾选联动**（选择带动关联区域变化）→ 筛选联动、选位后人数/价格实时联动更新。
3. **叠卡展开**（堆叠卡点开扇形展开）→ 活动卡展开看详情、船长卡展开，列表不跳页先看全。
4. **吸附**（拖动自动对齐吸附；原展示的画线标注本产品不用）→ 底部抽屉（行程/订单卡）拖动吸附档位。
5. **惯性滚轮**（惯性滚动选择器）→ 出航日期、人数选择。
6. **圆形扩散转场**（自点击点扩散揭页）→ 列表进入活动详情的转场。

## 借鉴纪律（创始人与 Muse 口径）
- 借的是**动效语言与质感**，不是抄视觉资产：不使用展示稿的配色、图标与署名元素；一切以现行品牌（深海墨绿＋荧光黄、VoltBank 风）重做。
- 高级感来自**一致与克制**：全 App 一套动效系统（时长/曲线/反馈方式统一），重点链路（选位、预订、成团进度）优先，其余页面不堆特效；过度动效反而廉价。
- 性能红线：Flutter 原生实现、目标 60fps、低端安卓不卡顿；动效不得拖慢交易主链路，不得改变信息字段与流程口径（与设计任务书冲突时以任务书为准）。
- 验收方式：随 UI 打磨批次单独走查，逐项对照本清单落点录屏自检；未实现项不视为缺陷，属排队增强。

交接四项：事项＝微交互借鉴清单；认领人＝Codex（开发线，随 UI 批次实现）；交付物＝对应页面动效；证据位置＝届时走查录屏与本仓记录。
