## 已实现口径

1. **来源和重量**：仅读取切片 1 的船长整船回填、乘客本人回填；只有 `max_individual_weight_grams` 有值才参榜。长度未持久化，因此没有新增长度采集或尺寸榜。
2. **月份、排序和数量**：按完成返航班次的 `return_at` 归入 `Asia/Shanghai` 自然月；可选当前月和有已返航班次的历史月份。每个标准鱼种最多 20 条，最大个体重量降序，源记录 `created_at` 较早者优先，并用来源、报告和条目 ID 作稳定的最终排序。
3. **双源归并键与取值**：按 `(departure_id, fish_code)` 归并同航次同鱼种的船长与乘客来源；候选来源中取最大个体重量最高者，同重取较早的源报告时间。这样每个航次、鱼种至多一条榜单记录，不会把同一条鱼因双源回填重复计榜。
   - **需 Dot 裁定的模型限制**：现有数据没有单鱼 ID 或跨来源关联键，船长记录是整船口径、乘客记录是个人口径，因此不能可靠证明两个来源说的是同一条个体鱼。当前保守归并也会把同一航次同鱼种的不同钓获者压成一条，并可能让船长整船最大个体覆盖某位乘客的较小个体。请 Dot 判断这一归并是否足以继续；如需逐人保留且仍可靠去重，需要另定数据模型，当前实现未臆造关联语义。
4. **待核对联动**：请求时直接从数据库计算。乘客自己的 reconciliation 为 `pending_review` 时排除其记录；航次出现任一 `pending_review` 时排除船长整船记录。状态恢复后下一次查询按现有事实重算，符合条件的记录会重新出现；没有新增审核、申诉或人工榜单维护流程。
5. **展示与隐私**：钓获人显示乘客 `display_name` 昵称（缺失时显示“钓友”）；不能归属到具体乘客的船长整船记录显示“船长回填”。展示船长名、返航日期和重量，不返回乘客实名、联系方式或订单身份信息。页面明确注明“数据来自渔获回填，不代表平台称重认证”。
6. **界面**：钓友首页增加“大鱼榜”入口；榜单页支持月份选择、按鱼种分组、重量排名、真实空状态和下拉刷新。无真机截图；Flutter Widget 测试覆盖榜单展示、月份切换和空状态，不能当作真机目检。
